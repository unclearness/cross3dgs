# Cross3DGS capture-to-view iOS app

iOS counterpart of the Android `:e2e` module
([`android/E2E_README.md`](../../android/E2E_README.md)): capture a
walk-around video with ARKit, extract sharp frames, run CPU COLMAP sparse SfM
with the AR priors, optimize Gaussians with the Cross3DGS Vulkan trainer
(MoltenVK), and inspect the result in a free-view orbit viewer — all on the
phone.

| Role | Target | Bundle ID |
|---|---|---|
| Training app | `cross3dgs_ios` | `org.unclearness.cross3dgs` |
| Capture-to-view integration | `cross3dgs_e2e_ios` | `org.unclearness.cross3dgs.e2e` |

As on Android, the two are separate apps; the training app has no camera or
SfM code.

## Pipeline parity with Android

| Stage | Android `:e2e` | iOS |
|---|---|---|
| Capture | ARCore Recording API MP4 + `arcore_poses.txt` | ARKit `capturedImage` → AVAssetWriter H.264 MP4 + `arkit_poses.txt` |
| Pose file | TUM rows, world_from_camera, +X right/+Y up/−Z fwd, `gravity_world 0 -1 0` | identical layout and convention (ARKit and ARCore share it) |
| Sensors | `sensors.csv`, Android sensor types | same columns and type ids; CoreMotion accel/gravity converted from g to m/s² with Android's sign, rotation vector = CoreMotion attitude quaternion (x y z w, arbitrary-yaw Z-vertical frame) |
| Extract | 2 candidates per uniform window, sharpest luma gradient, ≤1920 px, JPEG 92, interpolated priors | same algorithm (`AVAssetImageGenerator` at zero tolerance) |
| SfM | [`libs/cross3dgs_sfm`](../../libs/cross3dgs_sfm/README.md) through its JNI wrapper | the same `libs/cross3dgs_sfm` source, called through its C API |
| Optimize | `jni_bridge.cpp` `RunTraining` | `ios/e2e/app/E2eEngine.cpp`, same configuration, artifacts and bench.json schema (`backend: "Cross3DGS Vulkan iOS"`) |
| View | `renderOrbit` to SurfaceView | same orbit camera to a `UIImageView`; both use `cross3dgs/orbit_view.h` (gravity-aligned from the frame priors, level at any capture roll including portrait; orbits the subject the reference camera looks at, with the vertical turn limited when gravity is known) |
| Presets | Demo 3k/250k, Full 30k/1M, SH3 MCMC | same |

The capture records the largest ARKit video format whose long side is at most
1920 px (1920×1440 on iPhone 12 Pro), so frames are 4:3 rather than Android's
typical 16:9. ARKit exposes no autofocus state, so the pose file records
`autofocus_enabled true` instead of Android's per-frame `# focus` rows.

The run layout under `Documents/capture_to_view/` matches Android's
`files/capture_to_view/` (captures are SHA-256 sealed, every run is a new
directory, stage outputs are create-once, `project_manifest.json` uses the
Android keys with `schema_version` 6, the five stage screenshots (plus the
optional SfM-step `sfm_features` and `sfm_matching`) and the final inventory
gate `complete`). `pipeline_config` additionally records
`platform: ios`, the capture API and the frame decoder. Telemetry columns are
iOS-native: `phys_footprint` (the jetsam accounting), `os_proc_available_memory`,
thermal state and battery.

## Build

1. The SfM library (once; ~10 min on an M-series Mac, mostly vcpkg):

   ```sh
   git submodule update --init external/colmap
   git clone https://github.com/microsoft/vcpkg <vcpkg root>
   <vcpkg root>/bootstrap-vcpkg.sh
   brew install pkgconf
   scripts/build_ios_sfm.sh --vcpkg-root <vcpkg root> --out build-ios-sfm
   ```

   This builds libomp for iOS from the LLVM 19.1.7 OpenMP sources, the vcpkg
   dependencies for `arm64-ios-cross3dgs` (overlay triplet; overlay gklib port
   for iOS's missing `system()`; OpenColorIO's monitor query compiled out),
   COLMAP with BLAS/LAPACK from Accelerate, and merges everything into
   `build-ios-sfm/libcross3dgs_sfm.a`.

2. The app (Xcode project generated by CMake, like the training app):

   ```sh
   cmake -S ios -B build-ios -G Xcode -DCMAKE_SYSTEM_NAME=iOS \
         -DCMAKE_XCODE_GENERATE_SCHEME=ON -DCROSS_3DGS_IOS_TEAM=<team id> \
         -DCROSS_3DGS_IOS_BUNDLE_DATASET=OFF \
         -DCROSS_3DGS_IOS_SFM_LIBRARY=$PWD/build-ios-sfm/libcross3dgs_sfm.a
   xcodebuild -project build-ios/cross3dgs_ios.xcodeproj -scheme cross3dgs_e2e_ios \
         -configuration Release -destination 'platform=iOS,id=<udid>' \
         -allowProvisioningUpdates -allowProvisioningDeviceRegistration
   xcrun devicectl device install app --device <udid> \
         build-ios/Release-iphoneos/cross3dgs_e2e.app
   ```

   Signing needs an Apple ID in Xcode → Settings → Accounts; see
   [`../README.md`](../README.md) for device setup.

## Use

Tap **Capture**, walk slowly around the subject with the phone held so the
subject stays in view, and tap **Stop recording**. The app then extracts
frames, runs SfM, optimizes, and opens the viewer automatically (drag =
rotate, pinch = zoom, two fingers = pan). **Run saved capture**, **Replay
frozen SfM input** and **Open finished run** behave as on Android. **Share
PLY** sends `splat_gravity_up.ply` (world down rotated to +Y; `splat.ply` when
the run has no gravity priors) and `bench.json` through the share sheet (Files,
AirDrop, …); the run directories are also visible in the Files app.

Keep the app in the foreground: iOS suspends background compute, so a stage
does not continue behind the lock screen. The screen idle timer is disabled
while a stage runs.

Launch arguments for headless runs:

```sh
xcrun devicectl device process launch --device <udid> org.unclearness.cross3dgs.e2e \
    -image_folder test_images -preset demo
```

`-image_folder` (Documents-relative or absolute) starts a run from a folder of
JPEGs without AR priors, recorded as `capture_source: imported_image_folder`;
it exists to exercise SfM → optimize → view without walking the phone around.
`-saved_capture <id>`, `-run_id <id>`, `-auto_start YES`,
`-frame_target_count <n>`, `-preset demo|full`,
`-viewer_reference_image <name>` and `-sfm_preview NO` mirror the Android
intent extras. The last one turns off the SfM live preview (SIFT keypoints,
pair match-quality matrix, growing sparse model in the surface view while
SfM runs) for new runs; `pipeline_config.sfm_live_preview` records it.
